!!! note "Definition: PEG grammar"
    A grammar where alternatives are tried in order and the first one that matches wins.
    CPython has used one for its parser since 3.9.

!!! note "Definition: pegen"
    The parser generator of CPython (`Tools/peg_generator`, written in Python). It reads
    `Grammar/python.gram` and produces the parser.

!!! note "Definition: ASDL"
    Abstract Syntax Description Language, the notation used by CPython to describe the
    AST nodes (`Parser/Python.asdl`).

The CPython parser has four parts:

| Part      | File                                 | Nature |
| --------- | ------------------------------------ | ------ |
| Grammar   | `Grammar/python.gram`                | PEG grammar, with the node-building actions written in C |
| Parser    | `Parser/parser.c`                    | generated by pegen from the grammar, checked into the repo |
| Tokenizer | `Parser/tokenizer.c`                 | handwritten C |
| AST       | `Parser/Python.asdl`, `Python-ast.c` | node definitions, and C code generated from them |

The generated `parser.c` cannot be reused: its actions are C, and its output is CPython
objects. The plan is to [generate the node classes](node:pyast-nodes) from the ASDL file,
[port the tokenizer and helpers](node:pyast-tokenizer) by hand, and
[generate the parser](node:pegen-spy-backend) from the same grammar with a SPy backend
for pegen. The AST changes between CPython versions, so a target version must be chosen.
Differential testing is easy: parse the standard library with both parsers and compare
the `ast.dump` output.
